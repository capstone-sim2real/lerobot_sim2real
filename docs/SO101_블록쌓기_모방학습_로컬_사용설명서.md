# SO-101 블록 쌓기 모방학습 로컬 사용설명서

작성 기준:

- 작업 PC/Orin 홈: `~`
- LeRobot 본체: `~/lerobot`
- 팀 저장소: `~/lerobot_sim2real`
- 보고서: `~/my_report.tex`
- 실행 방식: 원격 서버 없이 Orin에서 데이터 수집, ACT 학습, 추론까지 로컬 진행

이 문서는 처음 LeRobot과 피지컬 AI 모방학습에 온보딩하는 단계의 반복 실험용 매뉴얼이다. 목표는 처음부터 경기용 5블록 탑쌓기를 바로 해결하는 것이 아니라, `카메라 확인 -> 리더암 시연 수집 -> 데이터 검수 -> ACT 학습 -> 실제 로봇 rollout -> 실패 보강` 루프를 손에 익히는 것이다.

## 1. 현재 파일/디렉토리 역할

### `~/my_report.tex`

졸업과제 계획서다. 핵심 요구는 다음과 같다.

- SO-ARM101/SO-101이 테이블 위 5개 블록을 집어 지정 영역으로 옮기고 쌓는다.
- 관측은 손목 카메라와 어깨/탑다운 카메라를 사용한다.
- 리더암 시연 데이터로 ACT 모방학습을 먼저 한다.
- 초기 배포는 Orin Nano 온디바이스 추론으로 검증한다.
- 이후 가능하면 서버 비동기 추론, sim-to-real로 확장한다.

## 2. 첫 추천 전략

바로 5개 블록을 쌓는 에피소드로 시작하지 않는다.

추천 단계:

1. 단일 블록을 집어 지정 영역 안에 내려놓기
2. 여러 시작 위치의 단일 블록 pick-and-place 안정화
3. 높이 쌓지 않고 지정 영역 안 기준 위치에 가지런히 놓기
4. 2개 블록 쌓기
5. 3개 이상 쌓기
6. 최종 5개 블록 경기 흐름

이유:

- 처음에는 카메라, 캘리브레이션, 데이터셋, 학습, rollout 파이프라인 자체가 더 큰 리스크다.
- 쌓기는 파지, 이동, 내려놓기, 높이 정렬, 탑 안정성이 모두 섞인 과제라 실패 원인 분리가 어렵다.
- ACT는 좋은 시연 분포를 강하게 따라가므로, 먼저 쉬운 성공 데이터를 만들고 실패 유형을 하나씩 확장하는 편이 빠르다.

1차 데이터셋은 `블록을 모아서 대충 던져놓기`가 아니라 `지정 영역의 일정한 위치/자세로 정확히 내려놓기`를 목표로 한다. 그래야 2차 쌓기에서 필요한 정렬 습관이 생긴다.

## 3. 환경 준비

### 3.1 가상환경 켜기

```bash
cd ~/lerobot
source .venv/bin/activate
```

### 3.2 필수 패키지 확인

현재 환경에서 `lerobot-record`, `lerobot-train`, `lerobot-replay`가 `datasets` extra를 요구할 수 있다. 아래 명령이 실패하면 다음 설치 명령을 실행한다.

```bash
python - <<'PY'
import torch
print("torch", torch.__version__, "cuda", torch.cuda.is_available())

for name in ["datasets", "accelerate", "serial"]:
    __import__(name)
    print(name, "ok")
PY
```

필요 시:

```bash
cd ~/lerobot
source .venv/bin/activate
pip install -e '.[core_scripts,training,dataset_viz]'
```

SO-101 모터 패키지까지 함께 새로 맞춰야 한다면:

```bash
pip install -e '.[feetech,core_scripts,training,dataset_viz]'
```

주의: Orin에서는 JetPack에 맞는 PyTorch가 중요하다. 위 설치 중 PyTorch를 크게 바꾸려 하면 중단하고, 먼저 `python -c "import torch; print(torch.__version__, torch.cuda.is_available())"` 결과를 확인한다.

### 3.3 로컬 데이터 저장 위치 고정

로컬 실험 데이터는 Hub에 올리지 않고 `~/lerobot_data`에 모은다.

```bash
export HF_LEROBOT_HOME=$HOME/lerobot_data
mkdir -p "$HF_LEROBOT_HOME"
```

이 줄은 새 터미널마다 다시 실행하거나 `~/.bashrc`에 넣는다.

## 5. 카메라 확인

이 문서에서는 기본적으로 다음처럼 부른다.

```text
어깨/탑다운 카메라: /dev/video0 -> shoulder
손목 카메라:       /dev/video2 -> wrist
```

카메라 노드는 재부팅이나 USB 재연결 후 바뀔 수 있다. 실제 화면을 보고 `shoulder`와 `wrist`가 맞는지 확인한다.

### 5.1 LeRobot 카메라 탐색

```bash
cd ~/lerobot
source .venv/bin/activate
lerobot-find-cameras opencv --record-time-s 4 --output-dir ~/camera_check
ls -lh ~/camera_check
```

저장된 이미지를 열어 `/dev/video0`이 어깨인지, `/dev/video2`가 손목인지 확인한다.

### 5.2 어깨 카메라 라이브 보기

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video0 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! autovideosink sync=false
```

종료:

```text
Ctrl+C
```

### 5.3 손목 카메라 라이브 보기

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video2 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! autovideosink sync=false
```

원격 PC에서 보는 방법은 기존 문서 `docs/SO101_원격카메라.md`를 사용한다.

### 5.4 데이터 수집용 카메라 설정 변수

```bash
export SO101_CAMERAS='{shoulder: {type: opencv, index_or_path: /dev/video0, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: /dev/video2, width: 640, height: 480, fps: 30, fourcc: MJPG}}'
```

프레임이 불안정하면 우선 해상도와 FPS를 낮춘다.

```bash
export SO101_CAMERAS='{shoulder: {type: opencv, index_or_path: /dev/video0, width: 320, height: 240, fps: 15, fourcc: MJPG}, wrist: {type: opencv, index_or_path: /dev/video2, width: 320, height: 240, fps: 15, fourcc: MJPG}}'
```

## 6. 데이터셋 이름 규칙

처음 추천 이름:

```bash
export HF_LEROBOT_HOME=$HOME/lerobot_data
export DATASET_REPO_ID=local/so101_pick_place_v1
```

LeRobot은 새 기록 세션을 만들 때 `DATASET_REPO_ID` 뒤에 시간 스탬프를 자동으로 붙인다. 기록 후 실제 데이터셋 ID를 아래처럼 잡는다.

```bash
export ACTUAL_REPO_ID=$(find "$HF_LEROBOT_HOME/local" -maxdepth 1 -type d -name 'so101_pick_place_v1_*' -printf 'local/%f\n' | sort | tail -1)
echo "$ACTUAL_REPO_ID"
```

데이터는 보통 여기에 생긴다.

```bash
echo "$HF_LEROBOT_HOME/$ACTUAL_REPO_ID"
```

## 7. 에피소드 기록

### 7.1 에피소드 1개 시작

화살표 키로 에피소드를 조기 종료/재녹화하려면 키보드 이벤트를 받을 수 있는 로컬 데스크톱 세션에서 실행하는 것이 가장 안정적이다. SSH/headless 환경에서는 키 입력이 안 잡힐 수 있으므로 그때는 `--dataset.episode_time_s`를 짧게 잡고 한 에피소드씩 기록한다.

```bash
cd ~/lerobot
source .venv/bin/activate

export HF_LEROBOT_HOME=$HOME/lerobot_data
export DATASET_REPO_ID=local/so101_pick_place_v1
export SO101_CAMERAS='{shoulder: {type: opencv, index_or_path: /dev/video0, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: /dev/video2, width: 640, height: 480, fps: 30, fourcc: MJPG}}'

lerobot-record \
  --robot.type=so101_follower \
  --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6086462-if00 \
  --robot.id=my_follower \
  --robot.cameras="$SO101_CAMERAS" \
  --robot.max_relative_target=10 \
  --teleop.type=so101_leader \
  --teleop.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6085435-if00 \
  --teleop.id=my_leader \
  --dataset.repo_id="$DATASET_REPO_ID" \
  --dataset.num_episodes=1 \
  --dataset.episode_time_s=30 \
  --dataset.reset_time_s=10 \
  --dataset.single_task="Pick up one block and place it neatly in the target area." \
  --dataset.push_to_hub=false \
  --dataset.streaming_encoding=true \
  --dataset.encoder_threads=2 \
  --display_data=true \
  --play_sounds=false
```

진행:

```text
Recording episode N
-> 리더암으로 블록을 집어 지정 영역에 내려놓는다.
-> 30초가 지나거나 오른쪽 화살표를 누르면 에피소드가 끝난다.
-> num_episodes=1이면 저장 후 종료된다.
```

### 7.2 현재 에피소드를 일찍 끝내고 저장

녹화 중:

```text
오른쪽 화살표(->)
```

현재 에피소드 기록 루프를 조기 종료한다. 실패가 아니라면 이 에피소드는 저장된다.

### 7.3 중간에 캔슬하고 같은 에피소드 다시 시작

녹화 중:

```text
왼쪽 화살표(<-)
```

현재 에피소드를 버리고 다시 녹화한다. 나쁜 시연, 충돌, 블록을 놓친 경우에는 `Esc`보다 왼쪽 화살표를 먼저 쓴다.

### 7.4 전체 기록 중지

```text
Esc
```

주의: `Esc`는 세션 중지용이다. 현재 버퍼가 나쁜 에피소드라면 먼저 왼쪽 화살표로 버리는 습관을 들인다.

응급 상황:

```text
Ctrl+C
```

## 8. 데이터셋 확인/검수

### 8.1 데이터셋 정보 보기

```bash
cd ~/lerobot
source .venv/bin/activate

export HF_LEROBOT_HOME=$HOME/lerobot_data
export ACTUAL_REPO_ID=$(find "$HF_LEROBOT_HOME/local" -maxdepth 1 -type d -name 'so101_pick_place_v1_*' -printf 'local/%f\n' | sort | tail -1)

lerobot-edit-dataset \
  --repo_id "$ACTUAL_REPO_ID" \
  --operation.type info \
  --operation.show_features true
```

### 8.2 특정 에피소드 영상/관절값 보기

```bash
lerobot-dataset-viz \
  --repo-id "$ACTUAL_REPO_ID" \
  --episode-index 0 \
  --mode local
```

원격/헤드리스 환경이면 `.rrd` 파일로 저장한다.

```bash
lerobot-dataset-viz \
  --repo-id "$ACTUAL_REPO_ID" \
  --episode-index 0 \
  --save 1 \
  --output-dir ~/dataset_viz
```

### 8.3 특정 에피소드 재생

실제 follower가 데이터셋 action을 그대로 다시 실행한다. 주변을 비우고 짧은 에피소드부터 한다.

```bash
lerobot-replay \
  --robot.type=so101_follower \
  --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6086462-if00 \
  --robot.id=my_follower \
  --robot.max_relative_target=10 \
  --dataset.repo_id="$ACTUAL_REPO_ID" \
  --dataset.episode=0
```

### 8.4 이전 에피소드 중 지정해서 삭제

삭제는 원본을 바로 손으로 지우지 말고 `lerobot-edit-dataset`를 사용한다.

새 데이터셋으로 저장:

```bash
export FILTERED_REPO_ID=local/so101_pick_place_v1_filtered

lerobot-edit-dataset \
  --repo_id "$ACTUAL_REPO_ID" \
  --new_repo_id "$FILTERED_REPO_ID" \
```

## 10. 학습된 정책 테스트

### 10.1 짧은 rollout

처음에는 블록을 잡기 전, 주변을 비우고 5~10초만 돌린다.

```bash

lerobot-rollout \
  --strategy.type=base \
  --policy.path="$POLICY_PATH" \
  --robot.type=so101_follower \

  --robot.id=my_follower \
  --robot.cameras="$SO101_CAMERAS" \
  --robot.max_relative_target=10 \
  --fps=30 \

  --display_data=true \
  --return_to_initial_position=true \
  --play_sounds=false
```

문제가 없으면 `--duration=30`으로 늘린다.

### 10.2 성공률 테스트

처음 성공률은 손으로 표를 만들어도 충분하다.

```text
정책: act_so101_pick_place_v1
데이터: so101_pick_place_v1, 50 episodes
카메라: shoulder /dev/video0, wrist /dev/video2
테스트: 10회

1 성공
2 실패 - 그리퍼 높이 높음
3 실패 - 블록 왼쪽으로 밀림
...
성공률: 6/10 = 60%
```

실패 유형별로 다음 데이터를 추가한다.

```text
블록 위치를 못 찾음 -> 시작 위치 다양화, shoulder 카메라 확인
접근은 하나 높이가 안 맞음 -> wrist 카메라에 파지 순간이 잘 보이게 수집
잡고 놓침 -> 그리퍼 닫는 타이밍과 들어올리는 속도 시연 보강
목표 위치에서 흐트러짐 -> 내려놓기 직전 정렬/정지 동작 보강
```

## 11. 반복 실험 루프

처음 1주차 루프:

```text
1. 모터/카메라 확인
2. pick-and-place 5 episodes 기록
3. dataset-viz로 5 episodes 확인
4. overfit 학습 1000 steps
5. rollout 10초
6. pick-and-place 20~50 episodes까지 추가
7. 나쁜 episode 삭제
8. ACT 20000 steps 학습
9. 10회 성공률 측정
10. 실패 유형만 보강 수집
```

권장 에피소드 수:

```text
파이프라인 확인: 5 episodes
첫 overfit:       5~10 episodes
첫 실제 모델:    50 episodes
안정화:          100~200 episodes
2블록 쌓기:       별도 50 episodes부터 시작
```

## 12. 쌓기 단계로 넘어가는 기준

다음 조건을 만족하면 2블록 쌓기로 넘어간다.

```text
단일 블록 pick-and-place 성공률이 같은 조건에서 70% 이상
블록을 목표 영역 안에 놓는 위치 오차가 눈에 띄게 줄어듦
손목 카메라에서 파지/내려놓기 순간이 안정적으로 보임
나쁜 episode를 삭제하고 다시 학습하는 루프가 익숙함
```

2블록 쌓기 데이터셋 이름 예:

```bash
export DATASET_REPO_ID=local/so101_stack2_v1
```

작업 문장:

```text
Pick up one block and place it on top of the base block.
```

2블록 쌓기에서 처음에는 시작 조건을 강하게 고정한다.

```text
base block은 항상 지정 영역 중앙에 둔다.
두 번째 블록만 집어서 올린다.
카메라 위치는 pick-and-place와 동일하게 고정한다.
성공 후 5초 유지까지 사람이 확인한다.
```

그 다음에 한 에피소드 안에서 `첫 블록을 바닥에 놓고, 두 번째 블록을 그 위에 쌓기`로 확장한다.

## 14. 운영 원칙

- 한 데이터셋 안에서는 카메라 위치, 해상도, task 정의를 중간에 바꾸지 않는다.
- 실패한 시연은 학습 전에 삭제한다.
- 성공 데이터만 모으되, 시작 위치와 블록 자세는 조금씩 다양화한다.
- 처음에는 빠른 동작보다 일정하고 재현 가능한 시연이 더 좋다.
- 쌓기보다 먼저 `정확히 내려놓기`를 학습시킨다.
- 모델 성능이 애매하면 모델 구조를 키우기 전에 데이터를 눈으로 다시 본다.
- 매 실험마다 데이터셋 ID, 에피소드 수, 학습 steps, 성공률, 대표 실패 유형을 적는다.
