## 1. 목표와 최종 산출물

현재 탑캠 CV+IK가 계산한 파지 목표에 실제 그리퍼가 잘 맞지 않아 발생하는 실패를 줄인다.
보정 수집 단계에서는 손목캠과 Astra를 사용한다. Astra가 영상을 보고 실제 팔을 제한된
이동 도구로 조정하여 성공한 파지 명령을 찾는다. 그 명령과 기존 명령의 차이를
검증 가능한 보정 데이터로 저장하고, 결정론적인 보정 함수 또는 테이블을 만든다.

최종 운영은 탑캠 CV + 수치 보정 + 기존 IK/궤적/VERIFY만 사용한다.
Astra, API 연결, 손목 영상, 대화 이력 없이 동작해야 한다. Astra로 성공한 시연만으로
목표 달성을 선언하지 않는다. 파지 정확도 향상은 같은 조건의 보정 OFF/ON 비교와
미관측 위치 평가로 입증한다. 임의의 정확도 상한이나 성공률을 미리 보장하지 않는다.

산출물:
- 기존 관측·상대 이동·파지 기능을 연결한 보정 수집 도구와 dry-run
- 전후 이미지, 기존/성공 목표, 명령/실측 관절값, 파지 결과
- 적용 범위와 기준 설정을 함께 저장한 보정값 또는 프로파일
- LLM 의존성이 없는 런타임 보정 모듈
- 보정 OFF/ON 및 손목캠 제거 상태 검증 결과

## 2. 현재 확인한 기준과 제약

기준 문서: [AGENTS.md](../../AGENTS.md), [현재 아키텍처](../architecture.md),
[에이전트 가이드](../guide/SO101_LLM_에이전트.md).

계획 작성 시 체크아웃의 src/configs/calib/venue_lab.json meta:
- fk_direct_pairs, 9점, calibrated_at=2026-09-13T21:09:42
- RMS 5.1454mm, 최악 LOO 13.5348mm
- grasp-z 평균 4.0580mm, 표준편차 0.7270mm
이는 파일의 적합 지표이며 실제 파지 정확도를 다시 측정한 결과가 아니다.
첫 실험에서 실제 사용하는 설정을 저장한다. mseoky 서버의
배포본과 이 worktree의 설정이 동일하다고 가정하지 않는다.

기준 default.yaml에는 grasp_tangential_offset_mm=15.0이 이미 들어 있다.
새 보정은 이 값을 포함한 기존 전체 파이프라인 대비 잔차인지, 기존 값을 대체하는
전체 보정인지 명시한다. 첫 실험은 기존 보정을 고정한 잔차 보정으로 시작한다.
기존 보정이 변경되면 기존 프로파일을 자동 적용하지 않는다.

- 작업 파일과 실험 자료는 이 worktree 안에 둔다. 기존 main과 다른 worktree는 보존한다.
- 실행 중인 카메라 서버는 종료·재시작·설정 변경하지 않는다.
  기존 장치는 HTTP/MJPEG로만 관측하고 /dev/video 장치를 중복 개방하지 않는다.
- 손목캠은 이번 실험을 위해 사용자가 제안한 개발용 추가 장비다.
  production의 AGENTS §8 탑캠 단독 구성은 그대로 유지한다.
  물리 장착 후 장치 식별, 가림, 케이블, 추가 카메라의 소유 경로를 확인한다.
  사용자가 카메라를 추가하고 서버를 재시작하여 shoulder/wrist HTTP 스트림을 제공하고 있다.
  현재 서버는 유지한다.
- 탑캠 위치와 기존 homography는 고정한다. 카메라가 움직이면 해당 자료의 유효성을
  재판정한다. 기존 캘리브레이션을 반복해서 다시 맞추는 것을 주 해결책으로 삼지 않는다.
- 버스는 ArmSession의 락을 잡은 한 실행기만 소유한다. 경쟁 프로세스가 있으면 열지 않는다.
- 원시 관절각과 자유로운 절대 좌표를 LLM에 노출하지 않는다(§16.3).
  사용자가 말한 move_to의 의도는 제한된 상대 이동 도구로 구현한다.
- 모든 실제 이동은 현재 실측 자세에서 기존 IK, TrajectoryPlayer, BaseRobotIO를 거친다.
  wrist_roll 중립, 틱별 델타 제한, max_relative_target을 유지한다.
- STOP은 CancellableRobotIO를 재사용한다. 추론 중에는 마지막 자세를 유지하며,
  중단 뒤 늦게 도착한 모델 응답은 실행하지 않는다. disconnect로 토크를 해제하지 않는다.
- src/policy, src/fsm/handlers.py, docs/report, third_party/lerobot은 수정하지 않는다.
- SDK와 하드웨어 import는 지연한다. JetPack 환경에 uv sync를 실행하지 않는다.

## 3. 무엇을 보정하는가

기록에서 다음 값을 구분한다. FK와 영상 정렬의 상세 분석은 필요할 때 추가한다.
1. CV가 인식한 블록 목표 p_cv
2. 기존 모든 오프셋을 거친 IK 입력 p_baseline
3. 명령 관절각 q_cmd와 실측 관절각 q_meas
4. 실측 관절각으로 계산한 FK 좌표 p_fk
5. 영상으로 관측한 턱/블록의 상대 정렬 상태
6. Astra 탐색 후 검증된 성공 명령 p_success

초기 학습 표적은 c = p_success - p_baseline이다.
이는 성공한 '명령의 차이'이며, 실제 TCP의 절대 위치 오차를 측정한 값이라고 부르지 않는다.
Astra의 px/mm 추정이나 자기 설명은 정답 레이블이 아니다. 실제 적용한 명령과
확인된 결과를 코드가 기록한다.

여러 jog의 요청 벡터를 단순 합산하지 않는다. 클램프·좌표계·미도달을 고려해 실제로
승인된 최종 목표와 기준 목표를 같은 프레임에서 비교한다. 팔 기준 radial/tangential
성분 변환은 고정된 기준 목표에서 수행하고, 각 jog 때 회전한 축을 섞지 않는다.
내부 IK의 m와 외부 기록의 mm 변환 지점을 하나로 고정한다.

블록을 밀어 이동시킨 뒤 잡은 경우, 다른 블록을 잡은 경우, 가림으로 대상이 불명확한
경우에는 원래 위치에 대한 보정 레이블로 채택하지 않는다. 원본과 배제 사유는 보존한다.
성공 파지 하나는 최적 중심의 증명이 아니므로 반복 성공과 닫기 직전 정렬을 함께 본다.

## 4. 실행 순서 — 한 지점에서 먼저 재현

기존 도구 연결 → 한 지점에서 Astra 보정 탐색 → Astra 없이 재현 →
여러 위치로 확장 → 최종 CV+IK에 적용한다.

첫 실험 전에 오차 원인을 모두 분류하거나 관측 정확도를 완벽하게 입증할 필요는 없다.
단계마다 광범위한 검증을 선행하지 않고, 실행 결과에 따라 필요한 확인을 추가한다.
실제 이동 전 dry-run, 이동 제한·STOP, 버스 단독 소유와 파지 확인은 유지한다.

### 1단계 — 최소 준비와 기존 파지 확인

- 현재 사용하는 설정을 저장하고 탑/손목 영상이 들어오는지 확인한다.
- 로봇 버스 사용 여부를 확인하고 기존 카메라 서버는 그대로 둔다.
- 같은 위치의 블록 하나를 기존 CV+IK로 몇 번 잡아본다.
- 실패 모습, 기존 목표, 명령/실측 관절값과 파지 결과를 남긴다.

전체 배포 코드·URDF·장비 조사, 해시 수집, 상세 실패 분류와 오차 분포 산출은
첫 실험의 선행 작업에서 뺀다. 이상이 보이면 해당 항목만 조사한다.
카메라 운영에는 기존 AGENTS §8을 적용하되 이 계획에서 별도 검사를 중복 추가하지 않는다.

### 2단계 — 기존 기능으로 Astra 실험 연결

기존 agent/session의 관측·상대 이동·파지 기능을 최대한 재사용한다.
첫 구현은 관측 → 상대 이동 → 파지 확인만 연결하고, 블록 초기화는 사람이 수행한다.
별도 manifest 시스템, 종료/초기화 API, 대규모 예외 재생 체계부터 만들지 않는다.

관측에는 탑/손목 영상과 현재 상태를 제공한다. Astra는 코드 한도 안에서 상대 이동을
요청하고, 로컬 코드가 기존 IK와 궤적으로 실행한다. 추론 중에는 자세를 유지한다.
이동이 끝나면 새 영상을 제공한다. 0.3초 추론 주기를 요구하지 않는다.

전체 pick_block은 PICK을 끝까지 수행하므로, 호출만 반복해서는 닫기 직전 보정을 할 수 없다.
기존 계획·모션을 재사용하여 실험 경로에서 접근 후 보정할 수 있게 연결한다.
production handler에 LLM 호출이나 대기 훅을 넣지 않는다.

재사용 후보: session/arm_session.py, session/relative.py, session/cancel.py,
agent/worker.py, agent/provider/, control/trajectory.py, control/ik.py,
control/sensing.py의 check_grasp, camera/frame_source.py.
session/place_correction.py의 배치 보정값은 파지 보정과 섞지 않는다.

새 튜너블은 config.py dataclass와 YAML에 두고 실측 전 값은 가정값이라고 표시한다.
검증은 변경에 직접 필요한 테스트와 dry-run, 이동 제한·STOP 확인으로 한정한다.
새 상태 핸들러를 만들면 AGENTS §13의 Mock 테스트를 추가한다.

### 3단계 — 한 지점에서 보정값 찾고 그대로 재현

초기 3개 지점 × 각 5회 계획을 없애고, 도달 가능한 한 지점의 블록 하나부터 시작한다.

1. 기존 CV+IK로 접근한다.
2. Astra가 손목/탑 영상을 보며 제한된 상대 이동으로 파지를 보정한다.
3. 실제 파지 성공을 확인하고 기존 목표와 성공 목표의 차이를 저장한다.
4. 팔과 블록을 같은 초기 조건으로 되돌린다.
5. Astra를 끄고 저장한 보정값만 적용해 다시 잡는다.
6. 재현되면 몇 번 반복하고 다음 위치로 넓힌다.

성공은 기존 위치·부하 판정과 리프트 후 블록 유지 관측으로 확인한다.
불명확한 파지를 성공으로 처리하거나 운반하지 않는다.
재현되지 않으면 그 시도의 전후 자료로 원인을 살핀다. 처음부터 전체 실패 유형을
분류하거나 통계 보고서를 만들 필요는 없다.

### 4단계 — 필요한 만큼 위치와 보정 방식을 확장

- 한 지점에서 재현되면 중앙·좌우·가까운 곳·먼 곳으로 넓힌다.
- 일정한 오프셋부터 적용한다.
- 위치에 따라 보정량이 달라지는 실측 결과가 나오면 팔 기준 저차 함수나 테이블을 추가한다.
- 처음부터 여러 모델을 비교하거나 개발/모델 선택/평가 세트를 나누지 않는다.
- 최종 적용에 사용할 수 있는 CV 목표·계획 자세·접근 조건만 보정 함수의 입력으로 쓴다.
- 손목 영상이나 Astra 출력이 최종 런타임의 필수 입력으로 남지 않게 한다.
- 측정한 범위 밖으로 임의 외삽하지 않는다. 적용 영역과 기준 설정을 함께 남긴다.

### 5단계 — 최종 CV+IK에 적용

- 기존 목표에 잔차 보정을 한 번 적용하고 기존 IK/궤적/도달 제한을 그대로 거친다.
- 기존 15mm 보정과 중복 적용하지 않는다. 관절 출력에 상수 델타를 덧붙이지 않는다.
- 보정 OFF/ON을 선택할 수 있게 하여 바로 비교하거나 되돌릴 수 있도록 한다.
- 미션 실행 경로에서 agent SDK를 import하지 않는다. VERIFY와 기존 재시도는 유지한다.
- 관련 테스트와 dry-run 후 실제 파지 결과를 확인한다.

### 6단계 — 최종 후보에서 확인

Astra 없이 반복 파지 → 보정에 사용하지 않은 새 위치 → 손목캠 제거 상태 순으로 확인한다.
손목캠 무게·케이블이 처짐에 영향을 줘 제거 후 성능이 달라지면 해당 차이부터 조사한다.
필요하면 고정 외부 카메라로 최종 기계 상태를 관측해 보정 데이터를 다시 얻는다.

정식 성공률·시간 평가는 최종 후보가 나온 뒤 수행한다.
이때 평가할 배치와 반복 수를 정하고 보정 OFF/ON을 같은 조건에서 비교한다.
초기 실험에 신뢰구간, 세션 분리, 온도별 분석을 일괄 요구하지 않는다.
추가 분석은 결과가 불안정하거나 특정 위치에서 악화될 때 수행한다.

마지막으로 5개 블록 전체 미션을 확인한다. 180초 제한은 외부 supervisor로 강제한다.
파지 개선과 운반·배치 결과는 구분하고, 아직 측정하지 않은 성능을 주장하지 않는다.

## 5. 기록 형식과 원인 분석

실험 자료는 experiments/astra_cv_ik/<run_id>/ 아래에 보관할 예정이다.
큰 이미지·원본 로그·API 대화는 로컬 제외 규칙으로 관리하고 자격증명은 기록하지 않는다.
Git에는 계획, 재현 코드, 비식별 요약, 검증된 소형 프로파일만 포함한다.

첫 기록은 다음으로 한정한다.
- 실험에 사용한 설정 사본
- 이동/파지 전후 이미지
- 기존 목표와 성공한 보정 목표
- 명령 관절값과 실측 관절값
- 파지 결과; 보정에 쓰지 못한 시도는 짧은 이유

별도 상세 manifest나 파일 해시 수집부터 구현하지 않는다.
프레임 시각, API 지연, 이동 클램프, 그리퍼 부하 원본, FK와 영상 잔차 등의 상세 기록은
지연·미도달·판정 오류처럼 해당 문제가 생겼을 때 추가한다.
기존 코드가 이미 제공하는 기록은 그대로 활용한다.
Astra의 설명과 실제 파지 결과는 구분한다. 실패 자료는 진단용으로 남기되
Task 3 학습 에피소드에 넣지 않는다.

영상상의 오차는 관측 가능 범위까지만 해석한다. 카메라 중심을 파지 중심으로
가정하지 않으며, 손목 카메라가 움직이면 픽셀→mm 관계도 변한다.
높이가 다른 턱/마커에 블록 윗면 homography를 그대로 적용하지 않는다.
실제 TCP를 측정하지 못하면 mm 정렬 정확도 대신 성공률과 픽셀 잔차를 분리해 보고한다.

## 6. 완료 정의와 첫 구현 순서

완료는 보정값 한 개를 찾는 것이 아니라 다음 네 항목을 모두 충족한 상태다.
- Astra 탐색으로 얻은 명령 보정을 반복 가능한 데이터로 남겼다.
- 보정 함수의 유효 범위와 기준 설정을 명시했다.
- LLM/손목 영상 없이 최종 CV+IK에서 보정을 적용했다.
- 보정 OFF 대비 실제 개선을 보지 않은 지점과 최종 장비 상태에서 확인했다.

첫 구현 순서:
1. 기존 관측·상대 이동·파지 기능 연결
2. 최소 기록과 dry-run, 이동 제한·STOP 확인
3. 손목 스트림 연결 및 한 지점에서 Astra 보정 탐색
4. 블록 초기화 후 Astra 없이 저장한 보정 재현
5. 결과를 보며 위치 확대·보정 함수·최종 CV+IK 통합

현재 완료: 새 worktree와 이 계획 문서 작성 및 실행 절차 간소화.
다음 작업: 기존 기능으로 최소 실험 도구 연결.
아직 실험 코드를 구현하거나 로봇을 움직이거나 카메라 서버를 변경하지 않았다.

## 부록: 2026-09-20 primitive 보정 실험

작업 호스트: `ehdrms@orin-1`, worktree `astra-cv-ik-calibration`.
기록: `experiments/astra_cv_ik/live-session/primitive-rounds/`.
아직 5개 scatter/gather 한 라운드를 완주하지 않았다. 계획 거절은 파지 실패와 별도로 센다.

### 확인된 문제와 변경

- 일반 이동은 Cartesian 10mm IK 지점마다 move_to/settle을 호출해 정지했다. 관절 경로를 연속 재생하고 끝에서 정착한다. 틱 델타/IO clamp/취소/시간 제한과 실제 FK 경로 이탈 검사를 유지한다.
- 프리미티브의 파지 후 IK가 기존 파지 기울기를 0도로 지웠다. 같은 좌표 (281.8,68.5,50)에서 모델 위치 오차는 0도 6.02mm, -3도 0.35mm였다. 이제 파지 계획의 기울기를 보존한다. 이는 IK 모델 수치이며 실물 정확도 자체가 아니다.
- 하중을 든 상태의 최종 관절 오차를 한 차례, 축당 최대 3도로 보정한다. 누적 학습값이 아니라 매번 현재 관절 피드백으로 계산한다. 느린 보정 후 wood-slow-tracking에서 명령 높이 약54mm 대비 FK 높이53.3mm를 확인했다.
- 하강 ContactMonitor의 signed 변화량 +132 -> -60을 192 증가로 세어 공중 접촉으로 판정했다. primitive는 부하 크기 증가 모드를 사용하며 높은 곳에서 감지되면 테이블 release를 승인하지 않는다. 기존 task runner의 센싱 기본 동작은 유지한다.
- 간섭 후보 탐색에 (forward15,left0), (forward15,left-10)mm를 추가했다. 25mm 기존 한도 안의 실험 후보이며 전역적으로 학습/확정한 보정치가 아니다.

### 실제 결과와 실패

- blue-outward-grasp: 파지/초기 리프트 성공. 추가 수직 상승 IK 거절. 기존 place_at_cell 도구로 (-6,1)에 배치, 카메라 위치오차10.6mm. 전후 wood 위치 변화가 있어 무간섭 성공으로 세지 않는다.
- wood-tilt-lift: 파지 성공, lift 최종 FK 오차로 정지/복구.
- wood-tracking-corrected: 파지 성공, 추가 보정 부하 감지로 정지/복구.
- wood-slow-tracking: 파지/50mm lift 성공. wood-primitive-place에서 (-6,-2) 이동 성공, 그러나 높이62mm에서 접촉 오판 후 release. 공중 release 실패로 기록한다. 이후 magnitude/높이 gate를 추가했다.
- green-scatter: trial_f+10_l+0 후보가 접근/닫힘 간섭 검사 통과. 실제 close_gripper에서 yellow가 약14mm 이동했다. 사용자 관찰과 전후 프레임 검출이 일치한다. 무간섭 파지 실패다. 이어 lift 보정 시 shoulder_lift load126.4 ->208으로 중단. 복구 완료.

### green-yellow 접촉 원인 진단

`green-neighbour-shift.json`: yellow 검출 (279.8,-74.9) -> (275.0,-87.7)mm. 접근/하강 중에는 거의 변하지 않았으며 닫힘 구간에서 이동했다.

URDF mesh를 기존 TCP에 그대로 붙이면 움직이는 턱이 베이스 +x 쪽으로 개폐한다고 예측하나 영상은 -y 쪽이다. `jaw_mount_yaw_deg=90`으로 mesh 방향을 보정했다. 같은 실패 장면 재생(`green-contact-model-replay.json`)에서 0도는 clear, 90도는 yellow/moving_jaw 충돌을 반환한다.

이 값은 영상 기반 방향 정렬이며 전체 3D 형상/원점/개폐 각도 매핑을 완전히 실측한 것이 아니다. `physical_geometry_verified=false`, 공간15mm 및 각도 불확실성을 유지한다. 단일 실패 재현을 전체 안전성 검증으로 해석하지 않는다. 블록 운반 체적과 다른 링크의 충돌은 이 턱 검사에 포함되지 않는다.

### 방향 보정 적용 후

39개 관련 테스트 통과. 제어 서버에 적용했고 camera8090은 유지했다. green-mount-corrected-approach는 후보 거절로 접근하지 않았다. yellow-mount-corrected는 trial_f+0_l-10 후보로 hover까지 접근했으나 하강/닫힘은 하지 않았다.

새 프레임에서 기존 5개 외의 작은 주황색 물체가 yellow 오른쪽에 보였다. 기존 타겟 검출 목록에 포함되지 않아 이 장면의 장애물 집합은 불완전하다. 이 물체의 footprint/높이 또는 보수적 keepout을 반영하기 전 yellow 하강은 금지한다. 빈손 home으로 복귀했다. 전체 반복 태스크 완료/무간섭 성공률 향상은 아직 입증하지 못했다.
