# SO-101 학습 & 배포 가이드 (데스크탑)

이 문서는 **데스크탑(GPU)에서** 하는 일 — ACT/SmolVLA 학습, 그리고 데스크탑 추론 + Orin 제어를 분리하는 비동기 서빙 — 을 정리합니다.

데이터 수집·데이터셋 관리·전송은 별도 문서입니다 → **[SO101_데이터수집_데이터셋관리_가이드.md](./SO101_데이터수집_데이터셋관리_가이드.md)**

## 왜 학습·추론을 데스크탑에서 하나 (Orin 제약)

역할 분담은 선택이 아니라 하드웨어가 강제합니다.

- **Orin GPU는 sm_87** — 설치된 torch(`2.11.0+cu128` 일반 휠)에 sm_87 커널이 없어, GPU 실행 시 `CUDA error: no kernel image is available` 로 죽습니다. `torch.cuda.is_available()`은 True지만 실제 커널 실행에서 crash. → **학습·추론 모두 데스크탑에서.** Orin은 데이터 수집 + 로봇 제어(robot_client) 담당.
- Orin GPU를 꼭 쓰려면 JetPack용 PyTorch(sm_87 포함)를 별도 설치해야 하며, 일반 `pip install torch`로는 안 됩니다.

```text
Orin:    데이터 수집 + robot_client(로봇 제어)
데스크탑: 학습(lerobot-train) + policy_server(추론)
```

---

## 1. 비동기 서빙 구조

```
Orin (robot_client)
  카메라 프레임 + 관절 상태 → [Tailscale/LAN gRPC] → 데스크탑 (policy_server)
                                                            ↓ 추론
  SO-101 실행 ← 액션 청크(최대 50) ←──────────────────────────
```

ACT/SmolVLA는 한 번에 청크(액션 여러 스텝)를 뽑으므로, Orin이 청크를 실행하는 동안 다음 추론이 병렬로 진행됩니다. 통신 방식은 gRPC(TCP 소켓) 위이며 Tailscale이면 WireGuard 터널을 탑니다.

---

## 2. 의존성 설치

**데스크탑 (WSL Arch, x86_64):** CUDA torch라 `uv sync` 한 번으로 됩니다.

```fish
cd ~/lerobot
uv sync --extra async --extra dataset --extra training --extra smolvla
```

GPU 확인:

```fish
uv run python -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

**Orin (robot_client용):** torch를 건드리지 않도록 async만 추가.

```fish
cd ~/lerobot
uv pip install --python .venv/bin/python "grpcio" "grpcio-tools"
# 또는: uv sync --extra async  (torch 재설치 여부 확인 후)
```

## 3. 학습 — ACT

처음부터 학습(사전학습 없음). 데스크탑에서:

```fish
cd ~/lerobot
uv run python -m lerobot.scripts.lerobot_train \
    --policy.type=act \
    --dataset.repo_id=local/so101_place_v1 \
    --dataset.root=/home/(whoami)/.cache/huggingface/lerobot/local/so101_place_v1 \
    --steps=20000 \
    --save_freq=5000 \
    --batch_size=8 \
    --output_dir=outputs/act_place_v1 \
    --policy.device=cuda \
    --policy.push_to_hub=false \
    --wandb.enable=false
```

학습 모델: `outputs/act_place_v1/checkpoints/last/pretrained_model`

## 4. 학습 — SmolVLA (VLA, 언어 조건부)

ACT와 달리 `smolvla_base`(450M)에서 **파인튜닝**하고, task 문장으로 색/작업을 구분합니다.

```fish
cd ~/lerobot
uv run python -m lerobot.scripts.lerobot_train \
    --policy.path=lerobot/smolvla_base \
    --dataset.repo_id=local/so101_place_v1 \
    --dataset.root=/home/(whoami)/.cache/huggingface/lerobot/local/so101_place_v1 \
    --rename_map='{"observation.images.top": "observation.images.camera1", "observation.images.wrist": "observation.images.camera2"}' \
    --batch_size=16 \
    --steps=8000 \
    --save_freq=2000 \
    --output_dir=outputs/smolvla_place_v1 \
    --job_name=smolvla_place \
    --policy.device=cuda \
    --policy.push_to_hub=false \
    --wandb.enable=false
```

ACT와 다른 핵심:

- **`--policy.path=lerobot/smolvla_base`** (type 아님). 첫 실행 시 베이스 다운로드.
- **`--rename_map`**: base가 카메라 3개(camera1/2/3)를 기대. 우리 2개(top/wrist)를 camera1/camera2로 매핑. rename_map을 주면 "camera3 없음" 검증도 건너뜀.
- `--policy.push_to_hub=false` 없으면 `'repo_id' argument missing` 에러.
- 로컬 데이터셋은 `--dataset.root` 필수.
- OOM이면 `--batch_size=8`. **학습 중 게임 등 GPU 점유 금지** → `CUDA error: unknown error`로 죽음.
- SmolVLA `chunk_size`는 50 고정. rollout에서 `--actions_per_chunk=100`을 줘도 50까지만 나옴.
- 데이터 수는 SmolVLA가 사전학습 덕에 ACT보다 적게 듦(색당 20~30부터).

중단 후 체크포인트에서 재개 (마지막 `save_freq` 지점부터):

```fish
uv run python -m lerobot.scripts.lerobot_train \
    --config_path=outputs/smolvla_place_v1/checkpoints/last/pretrained_model/train_config.json \
    --resume=true
```

## 5. policy_server 실행 (데스크탑)

서버를 **먼저** 켭니다. fps는 학습 데이터 fps에 맞추되, 네트워크가 빡세면 낮춥니다(15).

```fish
cd ~/lerobot
uv run python -m lerobot.async_inference.policy_server \
    --host=0.0.0.0 --port=8080 --fps=15
```

`PolicyServer started on 0.0.0.0:8080` 확인.

## 6. robot_client 실행 (Orin)

서버 확인 후 Orin에서. 모델은 **서버(데스크탑)가 로드**하므로 `--pretrained_name_or_path`는 데스크탑 기준 경로입니다.

**ACT:**

```fish
cd ~/lerobot
~/lerobot/.venv/bin/python -m lerobot.async_inference.robot_client \
    --robot.type=so101_follower \
    --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6086462-if00 \
    --robot.id=my_follower \
    --robot.max_relative_target=10 \
    --robot.cameras='{
        "top":   {"type": "opencv", "index_or_path": 2, "width": 640, "height": 480, "fps": 30},
        "wrist": {"type": "opencv", "index_or_path": 0, "width": 640, "height": 480, "fps": 30}
    }' \
    --server_address=<데스크탑_IP>:8080 \
    --policy_type=act \
    --pretrained_name_or_path=outputs/act_place_v1/checkpoints/last/pretrained_model \
    --actions_per_chunk=50 \
    --fps=15
```

**SmolVLA** — robot_client에는 rename_map 인자가 없으므로 **카메라 이름을 `camera1`/`camera2`로** 직접 줍니다(학습 매핑과 동일: camera1=top=index2, camera2=wrist=index0). 그리고 **`--task` 필수**.

```fish
    --robot.cameras='{
        "camera1": {"type": "opencv", "index_or_path": 2, "width": 640, "height": 480, "fps": 30},
        "camera2": {"type": "opencv", "index_or_path": 0, "width": 640, "height": 480, "fps": 30}
    }' \
    --policy_type=smolvla \
    --pretrained_name_or_path=outputs/smolvla_place_v1/checkpoints/last/pretrained_model \
    --task="Pick up the green block and place it inside the red tape area." \
```

색 구분 검증: 테이블에 초록·노랑 둘 다 놓고, `--task`를 green↔yellow로 바꿔가며(각각 robot_client 재시작) 맞는 색을 집는지 봅니다.

데스크탑 IP:

```fish
ip addr show eth0 | grep "inet "   # LAN
tailscale ip                        # Tailscale
```

## 7. 실행 순서 (중요)

```text
1. 데스크탑: policy_server 실행 → "PolicyServer started" 확인
2. Orin: robot_client 실행
3. 서버 로그: "Client connected" → "Receiving policy instructions" → "Running inference"
```

서버를 재시작하면 robot_client도 **반드시** 재시작. 서버만 재시작하면 클라이언트가 이전 세션 상태로 관측만 보내고 모델이 안 실려 `'NoneType' object has no attribute 'config'` 에러가 반복됩니다.

## 8. rollout 튜닝 (급발진·떨림)

로봇 로그는 `~/lerobot/logs/robot_client_*.log`. `QUEUE SIZE`가 0 근처로 자주 떨어지면 네트워크 굶주림, `Control loop (ms)`가 크게 튀면 스파이크.

- **`--robot.max_relative_target=10`** — 스텝당 이동 제한(급발진 안전 클램프). `clamped to be safe` 경고는 정상 동작.
- **`--fps=15`** — 제어 주기 여유 + 관측 전송 부하 절반. 관측 1장이 640×480 2대면 ~1.75MB라 Tailscale에서 스파이크의 주원인.
- **`--aggregate_fn_name`** — 청크 겹침 구간 blending:

| 옵션 | old/new | 특성 |
|---|---|---|
| `latest_only` | new만 | 반응 빠름, 경계에서 튐 |
| `weighted_average` (기본) | 0.3/0.7 | 균형 |
| `average` | 0.5/0.5 | 중간 |
| `conservative` | 0.7/0.3 | 제일 부드러움, 반응 느림 |

떨림/멍청함의 **근본 원인은 대개 데이터 부족**입니다. 후처리는 완화일 뿐이며, 로그상 연산·큐가 여유로우면 모델 문제입니다.

## 9. 네트워크 환경

| 환경 | 지연 |
|---|---|
| 유선 LAN (같은 공유기) | ~1ms, 가장 안정 |
| Tailscale direct (P2P) | 20~60ms, 청크 추론엔 충분 |
| Tailscale relay 경유 | 100ms+, 불안정 |
| WiFi | 불안정, 평가엔 유선 권장 |

`tailscale status`에 `direct`면 P2P. 평가 당일은 데스크탑-Orin을 같은 공유기 유선으로.

## 10. 자주 나는 문제

**`'NoneType' object has no attribute 'config'` 반복** — 서버만 재시작함. robot_client도 재시작.

**`config.json not found on the HuggingFace Hub`** — 모델 이름/경로 오류.

**`Feature mismatch ... camera1/2/3` (학습 시)** — SmolVLA base 카메라 이름 불일치. `--rename_map`으로 매핑.

**`'observation.images.top'` 키 에러 (rollout 시)** — robot_client 카메라 이름이 모델 기대와 다름. SmolVLA면 카메라를 `camera1/camera2`로 지정.

**`'repo_id' argument missing`** — `--policy.push_to_hub=false` 누락.

**`CUDA error: unknown error` (학습 중)** — 데스크탑에서 게임 등 GPU 점유. 독점 후 재시도.

**`no kernel image is available` (Orin에서 학습·추론 시)** — Orin은 sm_87 미지원. 데스크탑에서 실행.

**`attempted relative import ...`** — 스크립트 직접 실행. `-m lerobot.async_inference.robot_client`로 모듈 실행.

**로봇 연결 `Torque_Enable ... no status packet` / 카메라 `can't open`** — 이전 프로세스(robot_client/record/카메라 웹)가 포트·카메라 점유 중. `fuser /dev/ttyACM0 /dev/video0 /dev/video2`로 확인 후 kill. kill 후에도 모터가 응답 안 하면 팔로워 전원 재부팅 + USB 재연결 후 `so101_scan_motors.sh`.
