# SO-101 데이터 수집 & 데이터셋 관리 가이드 (Orin)

이 문서는 **Orin에서** 하는 일 — 텔레오퍼레이션 데이터 수집, 데이터셋 검수·관리, 데스크탑 전송 — 과 모방학습 실험 전략을 정리합니다.

> **역할 분담 (하드웨어가 강제):**
> - **Orin**: 데이터 수집 + 로봇 제어. (학습·추론 불가 — GPU가 sm_87이라 CUDA 커널 없음)
> - **데스크탑(GPU)**: 학습 + 추론 서빙 → [SO101_학습_배포.md](./SO101_학습_배포.md)
>
> "로컬(Orin) 단독으로 학습까지" 하는 모드는 없습니다. 수집은 여기, 학습·rollout은 학습·배포 가이드입니다.

기본 설치·캘리브레이션·문제 해결은 먼저 이 문서들을 봅니다.

## 1. 목표와 실험 단계

처음부터 5블록 탑쌓기를 바로 풀지 않습니다. 쉬운 성공 데이터부터 만들고 실패 원인을 분리합니다.

추천 단계:

1. 단일 블록을 집어 지정 영역 안에 내려놓기
2. 여러 시작 위치의 단일 블록 pick-and-place 안정화
3. 지정 영역 안 기준 위치에 가지런히 놓기
4. 2개 블록 쌓기
5. 3개 이상 쌓기
6. 최종 5개 블록 경기 흐름

1차 데이터셋은 "대충 던져놓기"가 아니라 "일정한 위치/자세로 정확히 내려놓기"를 목표로 합니다. 그래야 이후 쌓기의 정렬 습관이 생깁니다.

### 색 구분과 VLA

SmolVLA(VLA)는 task 문장으로 색/작업을 구분합니다("green block" vs "yellow block"). 색깔별로 나눠 모으되, 하나의 데이터셋으로 합쳐 단일 모델로 학습합니다. **지정구역 테이프가 빨강**이므로 빨강 블록은 task 문장이 겹쳐 혼동 — 다른 색부터 하고 빨강은 나중에.

## 2. 사전 준비 체크리스트

```bash
cd ~/lerobot_sim2real
./scripts/so101_scan_motors.sh
./scripts/so101_teleop.sh 30
```

확인:

```text
1. leader/follower 모터 ID 1-6 응답
2. 캘리브레이션 완료
3. 텔레오퍼레이션 정상 (블록 작업엔 15~30 Hz면 충분)
4. /dev/video0, /dev/video2 카메라 역할 확인
5. 팔 주변 충돌 위험 제거
6. 카메라 웹 뷰어(so101_camera_web.sh)는 종료 — record와 카메라 충돌
```

문제가 있으면 [SO101_문제해결.md](./SO101_문제해결.md).

Orin의 LeRobot venv에 수집·데이터 의존성만 있으면 됩니다. torch를 건드리지 않도록 필요한 것만 설치합니다(전체 `uv sync`는 JetPack torch를 덮어쓸 수 있음).

```bash
cd ~/lerobot
uv pip install --python .venv/bin/python "datasets>=4.7.0,<5.0.0" "av>=15.0.0,<16.0.0"
```

> Orin torch(`2.11.0+cu128`)는 sm_87 미지원이라 GPU 학습·추론이 안 됩니다. 여기서는 수집만 하므로 문제없습니다. 학습은 데스크탑에서.

## 3. 에피소드 기록

오늘 검증된 방식은 `lerobot-record`를 모듈로 직접 실행하는 것입니다. 핵심 플래그가 다 들어간 형태입니다.

```bash
cd ~/lerobot
~/lerobot/.venv/bin/python -m lerobot.scripts.lerobot_record \
    --robot.type=so101_follower \
    --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6086462-if00 \
    --robot.id=my_follower \
    --robot.cameras='{
        "top":   {"type": "opencv", "index_or_path": 2, "width": 640, "height": 480, "fps": 30},
        "wrist": {"type": "opencv", "index_or_path": 0, "width": 640, "height": 480, "fps": 30}
    }' \
    --teleop.type=so101_leader \
    --teleop.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6085435-if00 \
    --teleop.id=my_leader \
    --dataset.repo_id=local/so101_place_green_v1 \
    --dataset.num_episodes=30 \
    --dataset.single_task="Pick up the green block and place it inside the red tape area." \
    --dataset.episode_time_s=30 \
    --dataset.reset_time_s=5 \
    --dataset.fps=30 \
    --dataset.push_to_hub=false \
    --dataset.rgb_encoder.vcodec=h264
```

녹화 중 조작:

```text
→   현재 에피소드 저장하고 다음으로
←   현재 에피소드 버리고 재녹화
Esc 전체 중지
```

주의사항:

- **`--dataset.push_to_hub=false`** 없으면 마지막에 HF 업로드하려다 401/403으로 죽음(로그인 안 했을 때).
- **`--dataset.fps`** (top-level `--fps` 아님). `episode_time_s`는 한 에피소드 최대 녹화 시간(화살표로 조기 종료 가능), `reset_time_s`는 에피소드 사이 정리 시간.
- **카메라 이름 일관성:** 한 데이터셋 안에서 카메라 이름·해상도·fps를 바꾸지 않음. 나중에 병합하려면 데이터셋끼리도 이 설정이 같아야 함.
- **0프레임 크래시:** SSH에서 화살표 키가 연타로 잘못 인식돼 빈 에피소드가 저장되면 크래시. → 한 번씩만 확실히 누르고, 에피소드는 최소 몇 초는 녹화되게 함.
- **실패 데모는 반드시 `←`로 버림.** 저장하면 그 실패 동작도 학습됨.

이어붙이기(resume) — 같은 데이터셋에 계속 추가:

```bash
    --dataset.repo_id=local/so101_place_green_v1_YYYYMMDD_HHMMSS \
    --dataset.root=/home/ehdrms/.cache/huggingface/lerobot/local/so101_place_green_v1_YYYYMMDD_HHMMSS \
    --resume=true
```

`lerobot-record`는 실행 세션마다 이름에 `_YYYYMMDD_HHMMSS`를 붙입니다. resume 시에는 **정확한 타임스탬프 포함 이름** + **`--dataset.root`(폴더 경로) 필수**(없으면 에러).

### Orin 인코딩 제약

- **NVENC 없음:** Orin Nano에 하드웨어 비디오 인코더가 없음. `h264_nvenc`는 `Operation not permitted`로 실패. → 소프트웨어 **`h264`** 만. (`--dataset.rgb_encoder.vcodec` 유효값에 `libx264` 없음)
- **`streaming_encoding`은 비권장:** Orin에선 녹화 중 실시간 인코딩이 CPU를 뺏어 녹화가 오히려 버벅임. 끔.
- **record loop 22Hz 경고:** 듀얼 640×480×30fps는 Orin CPU엔 버거워 22Hz로 떨어지는 경고가 남. 정상이며 진행 가능(약간 드랍). 신경 쓰이면 해상도/ fps를 낮춰 **새 데이터셋**으로.

## 4. 데이터셋 검수

품질 나쁜 데이터를 늘려봐야 소용없습니다. 학습 전에 눈으로 확인합니다.

정보 보기:

```bash
~/lerobot/.venv/bin/python -m lerobot.scripts.lerobot_edit_dataset \
    --repo_id local/<데이터셋> \
    --root /home/ehdrms/.cache/huggingface/lerobot/local/<데이터셋> \
    --operation.type info
```

에피소드 영상/관절값 보기 (headless면 `.rrd` 저장):

```bash
~/lerobot/.venv/bin/python -m lerobot.scripts.lerobot_dataset_viz \
    --repo-id local/<데이터셋> --episode-index 0 \
    --save 1 --output-dir ~/dataset_viz
```

에피소드 재생 (로봇으로):

```bash
~/lerobot/.venv/bin/python -m lerobot.scripts.lerobot_replay \
    --robot.type=so101_follower \
    --robot.port=/dev/serial/by-id/usb-1a86_USB_Single_Serial_5AE6086462-if00 \
    --robot.id=my_follower --robot.max_relative_target=10 \
    --dataset.repo_id=local/<데이터셋> --dataset.episode=0
```

나쁜 에피소드 삭제:

```bash
~/lerobot/.venv/bin/python -m lerobot.scripts.lerobot_edit_dataset \
    --repo_id local/<데이터셋> \
    --root /home/ehdrms/.cache/huggingface/lerobot/local/<데이터셋> \
    --operation.type delete_episodes \
    --operation.episode_indices "[3, 7]"
```

> 여러 에피소드가 **하나의 mp4에 이어져** 저장되므로, 중간 하나 삭제도 영상 전체를 재인코딩합니다(비쌈). 애초에 녹화 중 `←`로 버리는 게 훨씬 낫습니다.

## 5. 데이터셋 관리 (이름·병합·백업)

**이름 규칙:** `local/so101_<동작>_<변형>_v<버전>` (예: `so101_place_green_v1`).

**task 문장을 색/작업별로 정확히.** VLA 색 구분의 근거가 됩니다.

**통합 마스터 1개로 관리:** 색깔별 repo를 따로 두지 않고, 색별로 모은 뒤 `aggregate_datasets`로 하나에 합칩니다. fps·해상도·카메라 이름이 같아야 합쳐집니다. task 문장은 에피소드별로 보존됩니다.

```bash
cd ~/lerobot
.venv/bin/python -c 'from lerobot.datasets.aggregate import aggregate_datasets; from pathlib import Path; base = Path.home() / ".cache/huggingface/lerobot/local"; aggregate_datasets(repo_ids=["local/so101_place_green_v1_T1", "local/so101_place_yellow_v1_T2"], aggr_repo_id="local/so101_place_v1", roots=[base / "so101_place_green_v1_T1", base / "so101_place_yellow_v1_T2"], aggr_root=base / "so101_place_v1"); print("병합 완료")'
```

새 색을 추가할 때마다 임시 데이터셋으로 모은 뒤 마스터에 병합 → 로컬 폴더 하나, HF repo 하나로 유지.

**HF Hub 백업** (git repo에는 데이터 올리지 않음 — 코드/문서만):

```bash
~/lerobot/.venv/bin/hf auth login   # Write 토큰
~/lerobot/.venv/bin/hf upload <계정>/so101_place_v1 \
    /home/ehdrms/.cache/huggingface/lerobot/local/so101_place_v1 \
    --repo-type=dataset --private
```

> `lerobot-record` 시 `--dataset.push_to_hub=true`로 하면(로그인 상태) 수집과 동시에 올라가 이 단계를 생략할 수 있습니다.

**HF Hub에서 받기** — 다른 팀원/기기(예: 학습용 데스크탑)에서 내려받을 때. private repo면 먼저 `hf auth login`.

학습·검수 시에는 명시적으로 받지 않아도, `--dataset.repo_id=<계정>/so101_place_v1`만 지정하면 LeRobot이 자동으로 캐시에 받아 씁니다(이때는 로컬 `--dataset.root` 불필요). 미리 폴더로 받아두려면:

```bash
~/lerobot/.venv/bin/hf download <계정>/so101_place_v1 \
    --repo-type=dataset \
    --local-dir ~/.cache/huggingface/lerobot/<계정>/so101_place_v1
```

우리 프로젝트 데이터셋(HF, private): `142spp/so101_place_v1`(병합 마스터, 51ep), `142spp/so101_place_green_v1`(31ep), `142spp/so101_place_yellow_v1`(20ep).

### Orin ↔ 데스크탑 전송 (Taildrop)

WSL에 ssh 서버가 없어 rsync가 안 되므로 Tailscale 파일 전송을 씁니다. **데스크탑 WSL 노드 IP로** 보냅니다(Windows 본체 노드 아님).

```bash
# Orin: 압축 후 전송
cd ~/.cache/huggingface/lerobot/local && tar czf /tmp/ds.tar.gz <데이터셋폴더>
sudo tailscale file cp /tmp/ds.tar.gz <WSL_Tailscale_IP>:

# 데스크탑 WSL: 수신 후 해제
cd ~/.cache/huggingface/lerobot/local
sudo tailscale file get .
sudo chown $USER ds.tar.gz && tar xzf ds.tar.gz
```

HF Hub에 올려뒀다면 데스크탑에서 `--dataset.repo_id`로 바로 받아 학습할 수도 있습니다.

## 7. 실패 보강 루프

성공률을 손으로 표를 만들어 기록합니다.

```text
정책: smolvla_place_v1 (초록31+노랑20)
테스트 10회
1 성공 / 2 실패-그리퍼 높이 / 3 실패-블록 왼쪽 밀림 ...
성공률: 6/10
```

실패 유형별 보강:

```text
블록 위치 못 찾음   -> 시작 위치 다양화, top 카메라 확인
높이 안 맞음        -> wrist 카메라에 파지 순간 잘 담기
잡고 놓침           -> 그리퍼 닫는 타이밍/드는 속도 보강
목표에서 흐트러짐   -> 내려놓기 직전 정렬/정지 동작 보강
```

권장 에피소드 수 (SmolVLA 기준, ACT는 더 필요):

```text
파이프라인 확인:  5~10
색당 최소 실용:   20~30
색당 안정:        40~50
5색 통합 목표:    100~150 (색당 20~30 × 5)
```

양을 무작정 늘리기보다 **실패 구간을 집중 보강**하고, 다양성(시작 위치·자세)이 개수보다 중요합니다.

## 8. 쌓기 단계로 넘어가는 기준

```text
단일 블록 pick-place 성공률 70% 이상 (같은 조건)
목표 영역 안 위치 오차가 눈에 띄게 감소
wrist 카메라에서 파지/내려놓기 순간이 안정적으로 보임
나쁜 에피소드 삭제→재학습 루프가 익숙함
```

2블록 쌓기 시작 시 초기 조건을 강하게 고정:

```text
base block은 지정 영역 중앙 고정
두 번째 블록만 집어 올림
카메라 위치는 pick-place와 동일
성공 후 5초 유지까지 확인
```

task 문장 예: `"Stack the block on top of the block in the red tape area."`

## 9. 운영 원칙

- 한 데이터셋 안에서 카메라 위치·해상도·task 정의를 중간에 바꾸지 않는다.
- 실패 시연은 학습 전에 버린다(녹화 중 `←`가 최선).
- 성공 데이터만 모으되 시작 위치·자세는 다양화한다.
- 빠른 동작보다 일정하고 재현 가능한 시연이 낫다.
- 쌓기보다 먼저 "정확히 내려놓기"를 학습시킨다.
- 성능이 애매하면 모델을 키우기 전에 데이터를 눈으로 다시 본다.
- 매 실험마다 데이터셋 ID·에피소드 수·학습 steps·성공률·대표 실패 유형을 기록한다.
