# 웹 키보드 연속 조작

WASD / J·K를 누르는 동안 이동한다. 단발 버튼의 이동 거리와 별개로
`agent.relative.keyboard_speed_mm_s`를 목표 경로 속도로 사용한다.

Ruckig의 속도 제어로 경로 속도·가속도 상태를 유지한다. 기본값은 20 mm/s,
가속도 100 mm/s², 저크 1000 mm/s³다. 정지→20 mm/s와 20 mm/s→정지는
각각 모델상 0.3초이며 정속에서 제동 거리는 3 mm다. 관절 속도 제한에 따라
목표 속도는 더 낮아질 수 있다. 이 값은 튜닝 출발값이며 실제 측정치가 아니다.

- 일반 키 해제: `/api/keyboard/release`로 감속 후 종료한다. 이후 입력은 거부한다.
- 방향 변경: 기존 방향으로 감속한 뒤 새 방향으로 가속한다. 단순히 속도를 0으로 재설정하지 않는다.
- 창 이탈/키보드 끄기: `/api/keyboard/stop`으로 즉시 스트림을 종료한다.
- 입력 갱신 만료/비상정지: 정상 감속을 기다리지 않고 기존 정지 경로를 사용한다.
- 다음 목표가 작업 범위/IK 검사를 통과하지 못하면 앞서 검사한 경로의 잔여 제동 구간에서 감속한다.
- 시작부터 제동 여유가 부족하면 이동을 시작하지 않는다.

보간은 단일 로봇 작업 스레드에서 수행한다. 경로 속도의 S 곡선은 관절별
가속도/저크의 엄밀한 제한이나 물리적 속도 추종을 보장하지 않는다. 기존
관절 속도·틱 간격당 변화량·하드웨어 제한은 유지한다. IK 계산 중의 간격은
여전히 남으므로 모의 테스트 통과를 실제 부드러움 검증으로 해석하지 않는다.

배포 환경에는 `pyproject.toml`의 agent extra에 선언된 `ruckig==0.19.4`가
필요하다. 없으면 시작 요청은 503으로 거부되며 로봇을 움직이지 않는다.
이번 검증에는 워크트리의 `.venv-keyboard-test`만 사용했고 실행 서버는 변경하지 않았다.
