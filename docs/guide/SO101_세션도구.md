# SO-101 세션 도구

저장소 루트에서 실행한다. 아래 명령은 설치된 CLI 대신 `python -m` 형식이라
editable 환경의 진입점 재설치 없이 사용할 수 있다. `uv sync --extra hardware`
후에는 `so101-teleop-session`, `so101-capture-teleop-points`, `so101-live-fk`도 제공된다.

## 파일 위치

- `src/`: 유지보수하는 실행 코드. `src/configs/calib/venue_lab.json`은 현재 적용본.
- `docs/guide/`: 사용법. `docs/calibration/`은 자료 이동 안내.
- `experiments/legacy/calibration/`: 날짜 미확인 이전 자료.
- `tests/fixtures/`: 테스트 전용 이미지.
- `experiments/2026-09-08/`: 당시 캘리브레이션, 이미지, 성공/실패 기록.
- 실험 세션의 `runtime_scripts/`: 당시 임시 코드 원본. 정식 실행 진입점은 아님.
- 실험 세션의 `archive/`: 이전 소스 백업과 교체 전 자료.
- `var/so101/`: 실행 중 요청, 관절 기록, FK 오버레이 JSON. Git에서 제외.

과거 JSON/CSV에 있는 절대 경로는 당시 출처 기록이다. 이동 후에도 그 값을
과거 기록으로 보존하며, 다시 분석할 때 입력 파일 경로는 명시적으로 지정한다.

## 권장 순서: 텔레옵을 유지하며 점 기록

이미 텔레옵이 켜져 있으면 두 번째 프로세스를 시작하지 않는다. 같은 팔의
시리얼 포트는 한 프로세스만 소유한다. 아래는 다음 세션을 시작할 때의 예다.
각 팔의 포트/ID/캘리브레이션을 확인하고 리더와 팔 자세를 맞춘다.

```bash
mkdir -p var/so101
# FOLLOWER_PORT와 LEADER_PORT는 실제 /dev/serial/by-id/ 경로로 지정한다.
env PYTHONPATH=src .venv/bin/python -m tools.teleop_session \
  --follower-port "$FOLLOWER_PORT" --leader-port "$LEADER_PORT" \
  --follower-id my_follower --leader-id my_leader \
  --runtime-dir var/so101 --capture-request var/so101/capture_request.json \
  --snapshot-url http://127.0.0.1:8090/snapshot/shoulder.jpg \
  --capture-max-delta 1 --fps 60 --step 5 --max-relative-target 10 \
  --seconds 0 --temperature-limit 65 --startup-limit 30 \
  --stable-seconds 1 --stable-delta 1 --dry-run
```

`--dry-run`은 시리얼 읽기와 캘리브레이션 확인까지 수행하지만 운동 명령을
보내지 않는다. 결과를 확인한 후 같은 명령에서 `--dry-run`을 빼면 추종한다.
기본은 시작 자세 차이를 유지하는 상대 추종이다. 사용자 선택 프로필의 절대
추종은 `--offsets-json`에 0 오프셋 파일을 명시한다. 과거 실험의 70 C 설정을
자동 적용하지 않으며, 다른 장비에 저장된 프로필을 자동 설치하지 않는다.

두 번째 터미널에서:

```bash
env PYTHONPATH=src .venv/bin/python -m tools.capture_teleop_points \
  --output-dir experiments/NEW_SESSION/calibration \
  --request var/so101/capture_request.json \
  --telemetry var/so101/observations.jsonl --count 9
```

이 명령은 팔에 직접 접속하지 않는다. 실행 중 텔레옵에 캡처를 요청하고,
팔을 비킨 사진의 노란 블록 중심을 검출한다. 사용자가 이미지를 검토하고
블록이 움직이지 않았음을 확인하면 저장한다. 중단 후 같은 명령으로 재개한다.
점 기록만 수행하며 적합·적용은 자동 수행하지 않는다. 그리퍼의 물리적 기준점과
URDF 기준점의 대응은 별도로 확인해야 한다.

## 실시간 FK 표시

```bash
env PYTHONPATH=src .venv/bin/python -m tools.live_fk_overlay \
  --telemetry var/so101/observations.jsonl \
  --output var/so101/gripper-reference.json
```

카메라 서버를 다음에 시작할 때 `--gripper-reference-path var/so101/gripper-reference.json`
옵션을 추가한다. 현재 실행 중인 구형 서버와 연결하려면 publisher의 `--output`을
그 서버가 읽는 경로로 지정한다. 서버를 임의로 재시작할 필요는 없다.

관절 기록은 텔레옵에서 약 1 Hz로 공급된다. 표시점은 FK의 XY를 캘리브레이션
평면에 투영한 위치이며 영상으로 검출한 집게 중심이 아니다. 기록이 오래되면
표시를 숨긴다. `--stale-after`, `--interval`로 유효 시간과 읽기 간격을 조절한다.

## 기존 명령의 역할

| 명령/모듈 | 용도 |
|---|---|
| `tools.capture_teleop_points` | **권장:** 텔레옵을 유지한 여러 점 기록 |
| `tools.capture_calibration_session` | 시리얼을 별도로 읽는 대화형 여러 점 기록 |
| `tools.capture_calibration_point` | 시리얼을 별도로 읽는 한 점 기록 |
| `tools.record_calibration_point` | FK·관절값·이미지만 저장하는 기본 도구 |
| `tools.pick_pixels` | 기존 사진의 중심을 사람이 클릭 |
| `tools.auto_pick_pixels` | 기존 사진의 색상 중심을 일괄 입력하는 구형 도구 |
| `tools.finalize_teleop_capture` | 저장된 관절 캡처를 FK CSV로 변환; 시리얼 접근 없음 |
| `tools.show_gripper_reference` | 시리얼을 읽어 FK 표시값을 한 번 저장 |

기존 명령과 옵션은 유지한다. 이전 자료의 기본 입력 경로는
`experiments/legacy/calibration/`, 새 캡처의 기본 출력 경로는
`experiments/current/calibration/`으로 변경했다. 명시적으로 지정했던 과거 경로는
[이동 안내](../calibration/README.md)에 따라 수정한다. 시리얼을 별도로 읽는 도구는
텔레옵 실행 중 사용하지 않는다. 새로 정리한 실행 경로는 소프트웨어 테스트로
검증했으며, 경로 정리 후 하드웨어 동작을 다시 실행하지 않았다.

## 공통 설정과 내부 역할

세션 도구는 모두 `--config`와 `--set session_tools.<키>=<값>`을 지원한다.
우선순위는 YAML → `--set` → 명시적 CLI 옵션이다. 기존 `--temperature-limit`,
`--stale-after`, `--timeout` 등도 그대로 사용할 수 있다.
`session_tools` 기본값은 `config.py`와 `src/configs/default.yaml`에서 함께 관리한다.
`--runtime-dir`을 바꾸면 명시하지 않은 요청/관절 기록/FK 파일 경로가 함께 바뀐다.

- `tools/session_io.py`: 관절 기록 읽기, JSON 원자적 쓰기, 캡처 요청·응답, JPEG 읽기.
- `tools/calibration_records.py`: 점 CSV, 완료 판정, 재시도 이름, accepted CSV 내보내기.
- `tools/calibration_pixels.py`: 검출·미리보기·확인된 픽셀 반영.
- `tools/teleop_session.py`: 인자 처리, 장치 생성, 읽기 점검, 정렬 대기, 추종, 종료 정리.
- `tools/capture_teleop_points.py`: 기록 선택, FK 캡처 요청, 픽셀 검토, 세션 재개.
- `tools/live_fk_overlay.py`: 인자 처리, FK payload 계산, 게시 루프.

수동 픽셀 클릭과 구형 색상 중심 검출은 사용 목적이 다르므로 명령을 합치지
않았다. CSV 읽기/쓰기는 공통 구현을 사용한다.
