# SO-101 원격 카메라 연결 가이드

Jetson/Orin에 연결된 USB 카메라 영상을 다른 PC에서 실시간 확인하는 방법입니다.

일반 확인용으로는 브라우저 기반 MJPEG 서버를 먼저 사용합니다. GStreamer UDP/RTP 방식은 지연을 더 줄이거나 별도 수신 파이프라인이 필요할 때 사용합니다.

## 1. 전제

```text
Jetson/Orin: USB 카메라 2대 연결
PC: 브라우저 접속 가능한 Windows/Linux/macOS
기본 방식: MJPEG over HTTP
보조 방식: GStreamer UDP/RTP 송출
사용 카메라 노드: shoulder=/dev/video0, wrist=/dev/video2
```

Jetson/Orin과 PC는 같은 LAN 또는 Tailscale 네트워크에 있어야 합니다.

## 2. 카메라 확인

Jetson에서 실행:

```bash
ls /dev/video*
```

보통 아래처럼 잡힙니다.

```text
/dev/video0
/dev/video1
/dev/video2
/dev/video3
```

일반적으로 실제 영상 노드는 `/dev/video0`, `/dev/video2`입니다. `/dev/video1`, `/dev/video3`은 보조 노드일 수 있습니다.

LeRobot 환경에서 확인하려면:

```bash
cd ~/lerobot
source .venv/bin/activate
lerobot-find-cameras
```

## 3. 브라우저로 실시간 확인

Jetson/Orin에서 실행합니다.

```bash
cd ~/lerobot_sim2real
so101-camera
```

인자 없이 실행하면 `0.0.0.0:8090`, shoulder `/dev/video0`, 1280×720,
30fps 및 `src/configs/default.yaml` 비전 오버레이가 기본 적용됩니다. 다른 값을
직접 지정하면 해당 값이 우선하며, 오버레이 프로세스까지 완전히 끄려면
`so101-camera --no-overlay`를 사용합니다.

정상 실행 시 아래 주소들이 출력됩니다.

```text
http://127.0.0.1:8090
http://JETSON_IP:8090
```

같은 네트워크의 PC 브라우저에서 아래 주소로 접속합니다.

```text
http://JETSON_IP:8090
```

기본 카메라 이름과 경로:

```text
shoulder -> /dev/video0
wrist    -> /dev/video2
```

이 이름은 모방학습 데이터셋의 카메라 feature 이름과 맞춰야 합니다. 학습 가이드의 기본값도 `shoulder`, `wrist`를 사용합니다.

직접 stream URL:

```text
http://JETSON_IP:8090/video/shoulder.mjpg
http://JETSON_IP:8090/video/wrist.mjpg
```

상태 확인:

```text
http://JETSON_IP:8090/health
```

웹 페이지는 원본 MJPEG 연결을 계속 유지하고, 검출 좌표만 SSE JSON으로 받아
브라우저 Canvas에서 합성합니다. `all`/색상 선택 중에도 영상 프레임률은 동일하며,
`none`을 고르면 Canvas를 숨기고 비전 분석 구독도 중단합니다. 녹색 사각형은
검출된 블록 외곽, 번호는 꼭짓점, `C`는 검출 중심, `B`와 자홍색 표시는 각각
명목 파지 보정점과 재시도점입니다. 주황색 원호는 로봇 베이스 기준 320mm의
표시용 탑다운 도달 경계이며 실제 도달 판정은 계속 IK가 담당합니다.

`so101-camera`의 브라우저 영상은 **MJPEG over HTTP/TCP**입니다. `MJPG` FOURCC는
USB 캡처 형식이며 UDP를 뜻하지 않습니다. 이 문서 뒤쪽의 GStreamer 명령을
별도로 실행할 때만 RTP/H.264 over UDP를 사용합니다.

포트나 카메라 경로, 오버레이 설정을 바꿔야 하면 CLI 인자를 사용합니다.

```bash
so101-camera --host 127.0.0.1 --port 9000 \
  --shoulder-device /dev/video2 --wrist-device /dev/video0 \
  --overlay-config src/configs/default.yaml
```

기본 해상도는 1280x720입니다. **CV+IK 경로에서는 이 값을 낮추지 마세요** —
캘리브레이션(`venue_lab.json`)이 1280x720 프레임 기준으로 만들어져 있고,
해상도를 바꾸면 화각까지 달라져서 좌표 변환이 어긋납니다.

프레임이 불안정할 때만, 그리고 캘리브레이션과 무관한 단순 확인 용도로만
해상도와 FPS를 낮춥니다.

```bash
so101-camera --width 320 --height 240 --fps 15 --no-overlay
```

주의:

```text
1. 웹 서버는 LAN 또는 Tailscale 안에서만 사용
2. 공인 인터넷에 직접 노출하지 않기
3. 데이터 수집/rollout 중 카메라를 이미 점유하고 있으면 동시에 열리지 않을 수 있음
4. 원격 조작 전에는 브라우저 영상으로 팔 주변 충돌 위험 확인
```

## 4. Windows PC IP 확인

Windows PowerShell 또는 CMD에서 실행:

```powershell
ipconfig
```

현재 네트워크 어댑터의 IPv4 주소를 확인합니다.

예시:

```text
192.168.0.20
```

아래 Jetson 송출 명령의 `PC_IP`를 이 값으로 바꿉니다.

Tailscale로 연결해서 사용할 경우에는 일반 Wi-Fi/LAN IP 대신 Windows PC의 Tailscale IP를 사용합니다.

Windows에서 확인:

```powershell
tailscale ip -4
```

예시:

```text
100.64.12.34
```

이 경우 Jetson 송출 명령에는 아래처럼 넣습니다.

```bash
udpsink host=100.64.12.34 port=5000 sync=false async=false
```

Tailscale IP를 쓰려면 Jetson과 Windows PC가 모두 같은 Tailscale 네트워크에 접속되어 있어야 합니다.

## 5. GStreamer로 카메라 1대 송출

### 5.1 Jetson에서 송출

`PC_IP`를 Windows PC IPv4 주소로 바꿔서 실행합니다.

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video0 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! \
x264enc tune=zerolatency speed-preset=ultrafast bitrate=2500 key-int-max=15 ! \
h264parse ! rtph264pay config-interval=1 pt=96 ! \
udpsink host=PC_IP port=5000 sync=false async=false
```

예시:

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video0 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! \
x264enc tune=zerolatency speed-preset=ultrafast bitrate=2500 key-int-max=15 ! \
h264parse ! rtph264pay config-interval=1 pt=96 ! \
udpsink host=192.168.0.20 port=5000 sync=false async=false
```

### 5.2 Windows에서 수신

PowerShell 또는 CMD에서 한 줄로 실행합니다.

```powershell
gst-launch-1.0 -v udpsrc port=5000 caps="application/x-rtp,media=(string)video,encoding-name=(string)H264,payload=(int)96,clock-rate=(int)90000" ! rtpjitterbuffer latency=0 ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! autovideosink sync=false
```

정상이라면 Windows에 영상 창이 뜹니다.

## 6. GStreamer로 카메라 2대 송출

포트는 카메라별로 다르게 씁니다.

```text
/dev/video0 -> UDP 5000
/dev/video2 -> UDP 5002
```

### 6.1 Jetson 터미널 1

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video0 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! \
x264enc tune=zerolatency speed-preset=ultrafast bitrate=2500 key-int-max=15 ! \
h264parse ! rtph264pay config-interval=1 pt=96 ! \
udpsink host=PC_IP port=5000 sync=false async=false
```

### 6.2 Jetson 터미널 2

```bash
gst-launch-1.0 -v \
v4l2src device=/dev/video2 do-timestamp=true ! \
'image/jpeg,width=640,height=480,framerate=30/1' ! \
jpegdec ! videoconvert ! \
x264enc tune=zerolatency speed-preset=ultrafast bitrate=2500 key-int-max=15 ! \
h264parse ! rtph264pay config-interval=1 pt=96 ! \
udpsink host=PC_IP port=5002 sync=false async=false
```

### 6.3 Windows 터미널 1

```powershell
gst-launch-1.0 -v udpsrc port=5000 caps="application/x-rtp,media=(string)video,encoding-name=(string)H264,payload=(int)96,clock-rate=(int)90000" ! rtpjitterbuffer latency=0 ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! autovideosink sync=false
```

### 6.4 Windows 터미널 2

```powershell
gst-launch-1.0 -v udpsrc port=5002 caps="application/x-rtp,media=(string)video,encoding-name=(string)H264,payload=(int)96,clock-rate=(int)90000" ! rtpjitterbuffer latency=0 ! rtph264depay ! h264parse ! avdec_h264 ! videoconvert ! autovideosink sync=false
```

## 7. 종료

Jetson 송출 터미널과 Windows 수신 터미널에서 `Ctrl+C`를 누릅니다.

웹 카메라 서버도 실행 터미널에서 `Ctrl+C`로 종료합니다.

## 8. 트러블슈팅

### 8.1 브라우저에서 접속이 안 됨

확인할 것:

```text
1. Jetson/Orin에서 `so101-camera`가 실행 중인지 확인
2. PC에서 http://JETSON_IP:8090 으로 접속했는지 확인
3. Jetson/Orin과 PC가 같은 LAN 또는 Tailscale에 있는지 확인
4. 방화벽이 8090 포트를 막고 있지 않은지 확인
```

Tailscale IP 확인:

```bash
tailscale ip -4
```

### 8.2 웹 페이지는 뜨는데 카메라가 안 나옴

확인할 것:

```text
1. /dev/video0, /dev/video2가 실제 영상 노드인지 확인
2. 다른 프로세스가 카메라를 점유하고 있지 않은지 확인
3. SO101_SHOULDER_CAMERA, SO101_WRIST_CAMERA 값 확인
4. 해상도/FPS 낮춰서 재시도
```

```bash
ls /dev/video*
cd ~/lerobot
source .venv/bin/activate
lerobot-find-cameras
```

### 8.3 Jetson에서 `gst-launch-1.0`이 없음

Jetson에서 설치:

```bash
sudo apt update
sudo apt install gstreamer1.0-tools \
  gstreamer1.0-plugins-base \
  gstreamer1.0-plugins-good \
  gstreamer1.0-plugins-bad \
  gstreamer1.0-plugins-ugly \
  gstreamer1.0-libav
```

`x264enc` 확인:

```bash
gst-inspect-1.0 x264enc
```

### 8.4 Windows에서 `gst-launch-1.0`이 없음

Windows에 GStreamer를 설치한 뒤 확인합니다.

```powershell
where.exe gst-launch-1.0
gst-launch-1.0 --version
```

명령어가 안 잡히면 GStreamer의 `bin` 폴더를 PATH에 추가하고 PowerShell/CMD를 새로 엽니다.

### 8.5 Windows에서 명령어 문법 에러

Windows에서는 우선 한 줄 명령어를 사용합니다. Linux 줄바꿈 문자 `\`를 Windows에 그대로 붙여 넣으면 에러가 날 수 있습니다.

### 8.6 수신 창이 안 뜸

확인할 것:

```text
1. Jetson 송출 명령의 host=PC_IP가 Windows PC IPv4 주소인지 확인
2. Jetson 송출 포트와 Windows 수신 포트가 같은지 확인
3. Windows 방화벽에서 UDP 5000/5002 허용
4. Jetson과 Windows가 같은 네트워크인지 확인
5. /dev/video0, /dev/video2가 실제 영상 노드인지 확인
```

### 8.7 화면이 검게 나옴

확인할 것:

```text
1. /dev/video1, /dev/video3 대신 /dev/video0, /dev/video2 사용
2. 카메라 하나만 연결해서 테스트
3. 해상도/FPS 낮추기
4. USB 허브 대신 Jetson 본체 포트 사용
```

정지 이미지로 먼저 확인:

```bash
sudo apt install fswebcam
fswebcam -d /dev/video0 -r 640x480 --skip 30 --no-banner test0.jpg
fswebcam -d /dev/video2 -r 640x480 --skip 30 --no-banner test2.jpg
```

### 8.8 `nvv4l2h264enc` 에러

이 문서는 NVIDIA 하드웨어 인코더 대신 `x264enc`를 사용합니다. 아래 에러가 떠도 이 문서의 명령어에는 영향이 없습니다.

```text
No such element or plugin 'nvv4l2h264enc'
```

### 8.9 DeepStream 또는 Argus 경고

USB 카메라는 `v4l2src`를 사용합니다.

```bash
v4l2src device=/dev/video0
```

DeepStream 플러그인 경고나 Argus 경고가 떠도 영상이 정상적으로 뜨면 무시해도 됩니다.
